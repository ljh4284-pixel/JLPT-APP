## 항목별 판단
표기: 동의 / 일부 동의 / 보류(반대)

### 1. 콘텐츠 규모 — 동의
- 급수당 700개는 "핵심 단어장"으로 부르고, 확장은 실사용 뒤에 판단. N1 은 N2 실사용 후 착수.
- 조치: 단어 데이터에 `tier`(core/ext, 기본 core) 추가. 선정 근거 문서 docs/word_sources.md 작성(참고한 목록 이름, 판단이 갈린 단어). 진도 화면 문구를 "핵심 단어장 700개 중 학습 n개"로. id 고정은 이미 지키고 있음(id 재사용 금지, 기록은 id 기준).
- "하루 5개 × 189일 ≈ 945개" 계산에 동의. 8단계 계획은 "이미 아는 단어" 처리가 핵심이 됨.

### 2. 레벨 테스트·완주 계획 — 대부분 동의 (8단계 설계 메모 수정)
- 유지: 모르겠음 분리, 건너뛰기, 재응시, 급수 수준 단정 안 함.
- 수정: 목적을 "학습 시작 위치 확인"으로 축소, 총 20~30문항, 자기 신고 급수와 인접 급수부터. 결과는 "읽기 확인 25문항 중 18문항 정답"처럼 문항 수로 표시, 찍기 보정식 삭제. 객관식 1회 정답은 "알고 있을 가능성" 상태로 두고 다른 날 재확인. 필요 신규 수와 권장 신규 수 분리, 신규 0개인 날 허용, 자동 증량 금지(기간 연장·범위 축소·시간 증가 중 선택 안내). 소요 시간은 유형별 실측으로 계속 갱신.

### 3. 유형 비중·B 조건 — 일부 동의
- C 의 정답 모호성: 데이터로 확인됨. 조치(제안, 사용자 결정 필요):
  - 안 1(추천): C 화면에 뜻 + 품사 + 예문 빈칸(일본어 예문에서 해당 단어를 ＿＿로 가리고 한국어 번역 함께) 제시. 문맥이 답을 좁힌다. 예문에서 단어를 찾지 못하는 경우는 스크립트로 목록화해 예문을 고친다.
  - 안 2: 한자 표기 + 뜻 → 읽기 입력(한자 읽기 산출). 모호성은 사라지지만 "뜻→단어" 방향 연습이 없어진다.
  - 안 3: 뜻만 유지하고 뜻이 겹치는 단어는 C 제외 플래그. 가장 간단하지만 72묶음이 빠진다.
  - 공통: 대체 정답은 검수 없이 일괄 허용하지 않음. 뜻이 완전히 같은 22묶음은 뜻에 구분 설명(예: "내리다(탈것에서)", "내리다(아래로 옮기다)")을 붙인다.
- 이름: "발음 입력" → "읽기 입력"으로 변경(화면·설정·문서·메모리).
- 비중: N4 이상 기본값을 A3·B1·C1 로 잠정 조정. C 효과는 실사용 뒤 판단.
- B 첫 노출 금지와 "A/C 에서 1회 맞힌 뒤" 조건 유지. "아는 단어" 판정은 8단계에서 별도 기준(다른 날 재확인)으로 둔다.
- 가나 단어의 B(뜻→읽기 선택)는 기록에 구분 표시 → 후순위(통계 개편 때).

### 4. 오답 생성 — 일부 동의
- 동의: 넓은 태그(basic·daily·abstract·degree)는 후보 자격·점수에서 제외. 읽기 유사성 점수 추가(첫 모라 같음, 탁음 차이 무시). 같은 표기의 다른 유효 읽기(JMdict)를 단어장에 `alt_readings`로 저장하고 오답에서 제외. 최소 점수 미달이면 다른 단어 오답을 억지로 넣지 않음(2+1 강제 안 함). 유효 오답 3개 미만이면 B 제외 유지.
- 보류: N5 에 다른 단어 오답 도입. N5 공식 형식이 소리 변형이라 현행 유지. 검증된 후보 집합 안에서 보기 순환은 후보가 충분해진 뒤.
- 태그 체계 분리: 이미 `tags`(내용)와 `confusion`(혼동)이 분리되어 있음. 한자 공유는 데이터가 아니라 계산으로 판단.

### 5. 단어장 검증 — 동의 (가장 먼저)
- 조치: 전체 JMdict(common 아님)로 대조. 판정을 3단계로: 통과 / 검토 목록(접두 お·ご 형태, 복합어, 표기 차이) / 보류. "검증 불가"와 "잘못된 단어"를 구분해 보고서에 따로 적는다. お·ご 자동 제거 규칙은 쓰지 않는다.
- 교체했던 단어 복귀: N5 お酒·ごめんなさい·おじさん·おばさん, N4 もうすぐ·お見舞い·応接間·お陰·お子さん·入学式·お寺·お客さん 을 새 id 로 다시 추가(대체했던 단어는 그대로 둠, 良い→いい 는 읽기 문제라 유지). 음성도 생성.
- 검수 항목 중 자동화: 예문에 단어(또는 어간)가 들어 있는지, 뜻 중복, 예문 읽기 가나 검사(기존), 예문 읽기와 예문 한자 문장의 대응은 형태소 분석 없이 완전 자동화가 어려움 → 검토 목록으로. 음성과 예문 읽기 일치는 복수 읽기 한자(明日·家·日·今日·一日·何·方 등)가 든 예문만 뽑아 청취 검수.
- 급수 근거: docs/word_sources.md 에 참고 목록(구 JLPT 출제기준 4급·3급 어휘표, 교재 어휘)과 "AI 판단"임을 명시. BCCWJ 빈도표는 N3 선정 보조로 검토(이용 조건 확인 후).

### 6. FSRS·판정 — 일부 동의
- 동의: 첫 글자 힌트 사용 → '다시'. 모호 문제·오류 단어는 평가 취소·단어 제외 기능(9번)으로 처리. 목표 유지율 0.9 를 코드 설정에 명시(ts-fsrs 기본값과 같음). "정착" 문구를 "복습 간격 21일 이상"으로. 대기 화면 문구를 실제 시각 기준으로.
- 보류: A/B/C 를 분리된 복습 일정으로 나누는 것. 지금 구조에서는 B/C 가 일정에 영향을 주지 않으면 그 카드가 계속 "기한 도래" 상태로 남아 세션이 꼬인다. 기록은 이미 유형별로 분리 저장되므로, 2주 실사용 후 "단어 × 능력" 분리를 다시 검토한다. 당장은 오답·힌트 → '다시', 정답 → 사용자 선택으로 유지.

### 7. 신규 출제 순서 — 동의
- 조치: 순수 함수로 순서를 계산(파일 순서·id 와 무관). tier 우선 → 분야·품사 섞기 → 같은 한자를 공유하는 단어는 같은 날 신규로 넣지 않음(以上·以下·以内·以外). 비교 복습은 후순위.

### 8. 구조·유지보수 — 동의
- 조치: 평가 버튼 중복 클릭 방지, 같은 날 신규 한도 추적(오늘 처음 학습한 단어 수를 차감), 백업 내보내기→복원 왕복 테스트, 음성 재생성 기준을 "입력 문장·목소리 설정 해시" manifest 로(바뀌면 재생성) + 서비스 워커 캐시 버전 갱신, Web Speech 폴백은 localService 음성만(없으면 재생 안 함과 안내).
- Capacitor 전환은 "모듈 교체만으로 끝"이 아니라는 전제로 9단계 항목(키보드 가림, 앱 복귀, 파일 공유)을 추가.

### 9. 빠진 기능 — 동의
- 지금 넣을 것: 문제 도중 "여기서 끝내기"(현재 문제까지), 홈에 미처리 복습 수 문구 보강, 직전 평가 취소, 단어 신고·일시 제외(설정에서 복구), 마지막 백업 시점 표시, 세션 시간 제한 옵션(5/10분, 끄기).
- 통계: A/B/C 등급을 보조로 내리고 유형별 정답률, 힌트 없이 맞힌 비율, 다음 날 이후 첫 시도 정답률을 표시 → 8단계 전 간단판.
- 미루기: N1 대량 제작, 정교한 적응형 테스트, 추가 목소리, 이미지 카드, 다른 언어 범용화, 스토어 포장. 동의.

## 제안하는 진행 순서 (확정 전)
1. 검증 정책 수정 + 교체 단어 복귀 + 자동 검수 스크립트 + 선정 근거 문서 (콘텐츠 파이프라인)
2. 판정·출제 규칙 수정: 힌트→다시, C 제시 방식 변경과 모호 단어 처리, 이름 변경, 비중 조정, 오답 규칙 개선(넓은 태그 제외·읽기 유사성·alt_readings), 신규 출제 순서, 문구 수정
3. 짧은 세션과 안전장치: 도중 종료, 신규 한도 추적, 중복 클릭 방지, 평가 취소, 단어 제외, 백업 시점, 시간 제한 옵션, 음성 폴백 로컬 제한, 음성 manifest
4. 사용자 2주 실사용(소요 시간·다음 날 회상·부당 오답·중단 이유 기록). 같은 기간에 N3 핵심 700개 제작을 병행(콘텐츠 작업은 코드와 독립, 단 1번이 끝난 뒤 시작)
5. 실사용 결과 반영 → 8단계 간소판(시작 위치 확인 + 완주 계획) → N2 핵심 700개
검토자 제안과 다른 점: N3 제작을 실사용 뒤로 미루지 않고 병행한다(사용자 수준이 N4 를 넘을 가능성이 커서 실사용 단어로 N3 가 필요할 수 있음).
