문서를 읽어보니, **학습 앱의 기본 구조는 잘 잡혀 있지만, 지금은 단어장을 더 늘리기 전에 ‘무엇을 알았다고 판정할 것인가’와 ‘매일 부담 없이 쓸 수 있는가’를 먼저 검증해야 하는 단계**라고 생각합니다.

특히 유지할 만한 선택은 분명합니다.

- **간격 반복과 인출 연습을 중심에 둔 점:** 답을 보기 전에 기억에서 꺼내는 연습은 외국어 어휘의 장기 기억에 도움이 된다는 연구 근거가 있습니다. 다만 이 근거가 현재의 문제 유형 비중까지 정당화하는 것은 아닙니다. (Karpicke & Roediger 2008)
- **런타임 AI 없이 작동하는 구조:** 비용과 응답 지연을 줄이고, 같은 문제를 재현해서 고치기 쉽습니다.
- **저장·음성·파일 기능의 분리, 백업, 자동 검사:** 1인 개발에서 유지해야 할 좋은 기반입니다.
- **‘합격 커리큘럼’ 대신 ‘어휘 완주 계획’이라는 표현:** 앱이 제공하는 범위를 정직하게 설명합니다.

아래는 문서의 9가지 질문에 맞춘 검토입니다. **실제 코드와 실행 화면은 확인하지 못했으므로 설계 리뷰로 봐주세요. 제안하는 비율·문항 수·기간은 검증된 최적값이 아니라, 실사용 검증을 시작하기 위한 초기값입니다.**

**1. 콘텐츠 규모 — ‘핵심 700개’에는 동의, ‘급수별 700개로 범위 완성’에는 반대합니다.**

공식 JLPT는 현재 시험의 어휘·한자·문법 목록을 공개하지 않습니다. 따라서 문서에 나온 급수별 어휘량도 개발 계획에 참고할 추정치이지, 충족하면 시험 범위를 완성하는 기준은 아닙니다. (jlpt.jp FAQ)

저라면 다음처럼 구분하겠습니다. 아래 수치는 **하위 급수와 중복되지 않는 추가 단어 수**입니다.

| 급수 | 당장 권하는 제작 범위 | 장기 확장 시 잡아둘 대략적인 규모 |
|---|---:|---:|
| N5 | 기존 700개 검수 | 부족한 기초 어휘 보충 |
| N4 | 기존 700개 검수 | 누락 영역 중심 보충 |
| N3 | 핵심 700개 | 약 2,000개 |
| N2 | 핵심 700개 | 약 2,300개 |
| N1 | N2 실사용 검증 후 착수 | 약 4,000개 |

오른쪽은 문서의 비공식 어휘량을 참고한 **개발 규모 가정**입니다. 지금 저 숫자를 채우려고 대량 생성할 필요는 없습니다.

N3 제작 전에 확정할 것은 최종 개수보다 다음 세 가지입니다.

- 단어에 `핵심/확장` 구분과 선정 근거를 남깁니다.
- 화면에는 **‘N3 핵심 단어장 700개 중 학습한 수’**라고 표시합니다.
- 급수나 수록 순서를 바꿔도 학습 기록이 유지되도록 단어 ID를 고정합니다.

또한 개발자님의 실제 목표와 분량을 맞춰야 합니다. 7개월을 약 210일로 잡고 시험 21일 전 신규 학습을 끝낸다면, 하루 5개로 처음 접할 수 있는 단어는 **약 945개**입니다. 이미 아는 단어가 얼마나 되는지에 따라 계획이 크게 달라집니다. 모든 사용자를 N5부터 순서대로 보내는 방식은 기본 경로로 강제하지 않는 편이 좋습니다.

**2. 레벨 테스트·완주 계획 — 방향에는 동의하지만, 현재 설계는 정확도와 구현 부담을 모두 과대평가하고 있습니다.**

**‘모르겠음’ 분리, 건너뛰기, 재응시, 급수 수준을 단정하지 않기는 유지**하셔도 좋습니다. 다만 다음 부분은 수정이 필요합니다.

| 현재 계획 | 문제 | 수정 제안 |
|---|---|---|
| 급수당 20~25문항 | 세밀한 어휘량 추정에는 적음 | ‘학습 시작 위치 확인’으로 목적 축소 |
| 낮은 급수부터 모두 확인 | 상급자에게 긴 준비 과정 | 자기 신고 급수와 인접 급수부터 확인 |
| ‘N2 어휘 중 아는 비율’ | 앱 단어장·표본의 대표성이 검증되지 않음 | ‘이번 읽기 확인 25문항 중 18문항 정답’처럼 표시 |
| 객관식 1회 정답 → 긴 간격 | 찍기·소거·일시적 기억도 통과 | ‘알고 있을 가능성’ 상태로 두고 다른 날 재확인 |
| 매일 필요한 신규 수 자동 증가 | 하루 쉬면 다음 날 부담이 커짐 | 필요한 수와 실제 권장 수를 분리 |

25문항으로 비율을 추정하면, 이상적인 단순무작위 표본이라고 가정해도 정답률 50% 부근의 95% 오차폭은 단순 근사로 **약 ±20%포인트**입니다. 여기에 문항 난이도와 찍기 문제가 더해집니다. ‘72%를 안다’처럼 정밀해 보이는 수치는 피하는 편이 맞습니다.

찍기 보정식 `정답 수 − 오답 수÷3`은 **모르는 문제를 4개 중 무작위로 고른다는 가정에서는 기대 점수가 0**이 됩니다. 하지만 실제 사용자는 일부 선택지를 제거하기도 하고, 사람마다 ‘모르겠음’을 누르는 기준도 다릅니다. 이 식만으로 실제 지식량을 복원할 수는 없습니다. 입력형 C에는 같은 보정을 적용해서도 안 됩니다.

초기 버전이라면 **총 20~30문항 이내의 시작 위치 확인**으로 줄이고, 부족한 판단은 이후 며칠의 실제 학습에서 보완하겠습니다. 읽기 결과와 뜻 회상 결과도 따로 보여주는 편이 좋습니다.

완주 계획은 다음 원칙을 권합니다.

> **필요 신규 수 = 남은 신규 단어 ÷ 남은 신규 학습일**
> **권장 신규 수 = 필요 신규 수와 시간상 감당 가능한 수 중 작은 값**

둘이 다르면 자동으로 학습량을 늘리지 말고, 기간 연장·핵심 범위 축소·학습 시간 증가 중 무엇이 필요한지 보여주세요. **신규 0개인 날도 허용**해야 합니다.

‘복습은 신규의 5~8배, 카드당 7초’는 임시 추정에만 사용하세요. A와 C의 입력 시간, 신규 제시, 예문 듣기, 피드백 읽기가 다릅니다. 첫 주부터 유형별 실측을 반영하되, 첫 주에는 장기 복습 부담이 충분히 드러나지 않으므로 이후에도 계속 갱신해야 합니다.

**3. 문제 유형 비중·B 출제 조건 — 회상 중심에는 동의, 상급일수록 C를 늘리는 규칙에는 근거가 부족합니다.**

‘어려운 문제를 많이 풀수록 시험 대비에 좋다’고 볼 수는 없습니다. JLPT 어휘 영역에는 한자 읽기뿐 아니라 문맥에 맞는 표현, 유의 표현, 용법 등이 포함됩니다. **한국어 뜻을 보고 일본어 읽기를 직접 입력하는 능력과 시험에서 필요한 어휘 이해는 겹치지만 동일하지 않습니다.** (jlpt.jp 시험 구성)

현재 C에는 더 직접적인 문제가 있습니다.

**뜻만 제시하면 정답이 하나로 정해지지 않을 수 있습니다.**

예를 들어 ‘고치다’라는 뜻만으로 특정 일본어 단어 하나만 정답 처리하면, 사용자가 다른 적절한 단어를 입력했을 때 부당하게 틀릴 수 있습니다. 이 경우 FSRS에도 잘못된 실패 기록이 쌓입니다.

다음 중 하나가 필요합니다.

- 뜻에 **용법·상황·품사**를 추가해 목표 단어를 좁힙니다.
- 문맥으로도 답이 충분히 특정되지 않는 단어는 C에서 제외합니다.
- 대체 정답은 검수해서 등록합니다. 뜻이 비슷하다는 이유로 일괄 허용하면 안 됩니다.

화면 이름도 ‘발음 입력’보다는 **‘단어 떠올리기’ 또는 ‘읽기 입력’**이 실제 동작을 더 정확히 설명합니다. 입력 정확도만으로 발음 자체를 평가하는 것은 아니니까요.

비중은 우선 N5의 `A2:B1:C1`을 유지하고, N4 이상도 `A3:B1:C1` 정도로 시험해보겠습니다. C의 시간을 더 쓰는 것이 며칠 뒤 기억 유지에 도움이 되는지 확인한 뒤 늘리는 편이 합리적입니다.

B의 첫 노출 금지는 유지해도 괜찮습니다. 다만 **‘신규 제시 화면에서 답을 방금 본 뒤 맞힘’은 장기 기억의 증거가 아닙니다.** B를 출제할 수 있는 조건과 ‘알고 있는 단어’ 판정은 분리하세요. 힌트 없이 실제로 떠올렸다면 A의 ‘어려움’도 B 출제 조건에 포함할 수 있습니다.

또한 가나 단어에서 B가 ‘뜻 → 읽기 선택’으로 바뀌면 한자 읽기와 다른 능력을 묻습니다. 같은 B 화면을 쓰더라도 통계에서는 구분해야 합니다.

**4. 오답 생성 — 규칙 기반에는 동의하지만, ‘생성 가능한 비율’보다 ‘오답의 타당성’을 우선해야 합니다.**

N4의 698개가 출제 가능하다는 것은 좋은 구현 지표입니다. 다만 **698개가 좋은 문제라는 뜻은 아닙니다.**

한자 읽기 문제에서 중요한 것은 ‘같은 분야의 단어인가’보다 **‘이 표기를 보고 실제로 잘못 떠올릴 법한 읽기인가’**입니다. `貿易 → 出席`이 어색한 이유도 여기에 있습니다.

다음 규칙을 권합니다.

- `basic`, `daily`, `work` 같은 넓은 태그는 오답 선정 점수에서 제외합니다.
- 공유 한자의 위치, 읽기의 유사성, 작은 가나·장음·탁음 등 **혼동 이유가 설명되는 후보**를 우선합니다.
- 해당 표기의 다른 유효한 읽기가 오답에 들어가지 않도록 검사합니다. 문맥에 따라 답이 달라지는 표기는 문맥을 주거나 출제를 제외합니다.
- ‘다른 단어 2개 + 소리 변형 1개’를 반드시 채우지 않습니다.
- 유효한 오답 3개가 없으면 B를 제외하는 현재 원칙은 유지합니다.

태그도 용도를 나누세요. 예를 들어 `병원·이동·금전`은 내용 분류용, `장음·탁음·같은 한자·유사 표기`는 혼동 분류용입니다. 내용 태그를 촘촘하게 만드는 것만으로 읽기 오답 품질이 해결되지는 않습니다.

N5에서도 타당한 다른 단어 오답을 섞을 수 있습니다. 다만 모든 문제에 의무적으로 넣을 필요는 없습니다.

고정된 후보를 만드는 방식은 디버깅에 유리합니다. 이후 후보가 충분해지면 **검증된 후보 집합 안에서만 보기 구성을 순환**시킬 수 있습니다. 보기의 위치는 별도로 섞어야 합니다.

**5. 단어장 검증 — common 전용 필터와 무관한 단어로의 교체는 가장 먼저 수정해야 합니다.**

문서에서 가장 명확하게 반대하는 부분입니다.

`もうすぐ → 打つ`, `入学式 → 歩道`, `お客さん → 職業`은 표기 수정이 아니라 **배워야 할 내용을 다른 내용으로 바꾸는 작업**입니다. 검증 도구의 수록 범위가 교육 내용을 결정하고 있습니다.

JMdict의 우선순위 표지는 여러 빈도·어휘 자료에 기반한 정보입니다. 단어의 존재 여부나 JLPT 필수 여부를 판정하는 절대 기준이 아닙니다. 또한 사전 구조에는 표기별로 가능한 읽기를 제한하는 정보도 있습니다. (JMdict DTD)

검증 결과를 다음 세 단계로 바꾸는 것이 좋겠습니다.

| 상태 | 처리 |
|---|---|
| 전체 JMdict에서 해당 표기·읽기 조합 확인 | 자동 통과 |
| 접두 형태·복합어·표기 차이 등으로 추가 확인 필요 | 검토 목록으로 이동 |
| 다른 신뢰할 만한 자료로도 확인되지 않음 | 출시 대상에서 보류 |

**‘검증 불가’와 ‘잘못된 단어’를 구분**하는 것이 핵심입니다. `お`나 `ご`를 무조건 제거해 통과시키는 규칙도 피하세요.

그리고 **1,400개 읽기 일치와 콘텐츠 전체 검수 완료는 다릅니다.** 최소한 다음 항목을 별개로 확인해야 합니다.

- 한국어 뜻이 해당 용법과 맞는지
- 예문이 그 뜻을 실제로 보여주는지
- 예문 읽기와 음성이 일치하는지
- C의 정답이 충분히 특정되는지
- 급수 배정에 어떤 근거가 있는지

급수 배정에는 참고한 교재·목록의 이름과 버전, 판단이 엇갈리는 항목을 남기세요. AI를 두 번 돌려 같은 답이 나왔다는 것만으로 독립 검증이 되지는 않습니다.

빈도 보조 자료로는 국립국어연구소의 **BCCWJ 어휘 빈도표**를 검토할 만합니다. 다만 문어 자료의 빈도를 그대로 JLPT 급수로 변환해서는 안 됩니다. 선정 우선순위를 보완하는 자료로 사용하세요. (clrd.ninjal.ac.jp)

**6. FSRS — 기본 파라미터에는 동의하지만, 입력되는 학습 결과를 먼저 바로잡아야 합니다.**

FSRS에서 ‘어려움’은 **정답을 기억해냈지만 힘들었다**는 뜻입니다. 기억하지 못한 경우를 ‘어려움’으로 기록하면 간격 추정이 왜곡될 수 있다는 점을 Anki 공식 문서도 명시합니다. (Anki Docs)

따라서 다음처럼 구분해야 합니다.

| 상황 | 권장 처리 |
|---|---|
| 힌트 없이 어렵게 회상 성공 | 어려움 |
| 기억하지 못해 답의 일부를 보여주는 힌트 사용 | 다시 |
| 입력 방법 안내만 확인 | 힌트 사용만으로 실패 처리하지 않음 |
| 모호한 문제·잘못된 정답 때문에 실패 | 판정 취소 또는 학습 기록 제외 |

**‘힌트 사용 시 어려움 고정’은 힌트의 내용에 따라 수정해야 합니다.**

또 하나는 **단어 하나의 FSRS 카드에 A/B/C 결과를 함께 넣는 구조**입니다.

- A는 읽기를 제공받은 상태에서 뜻을 떠올립니다.
- B는 읽기를 보기에서 알아봅니다.
- C는 뜻에서 단어의 읽기를 만들어냅니다.

B에서 쉽게 맞혔다고 C에서도 오래 기억한다고 볼 수 없습니다. 한 카드로 섞는 것이 무조건 불가능한 것은 아니지만, 유형이 바뀌면서 정답률과 복습 간격의 의미가 흔들립니다.

유지보수 부담을 줄이는 초기 대안은 **A를 기준 복습으로 두고 B/C는 별도 보조 연습 기록으로 관리하는 방식**입니다. 세 능력에 각각 복습 일정을 주려면 이후 `단어 × 능력` 단위로 분리하되, 하루 시간 안에서 출제량을 제한해야 합니다. 세 유형을 매번 모두 시키자는 의미는 아닙니다.

나머지 설정은 다음처럼 판단합니다.

- **10분 한 단계:** 초기값으로 유지할 수 있습니다. 다만 앱 안에서 기다려야 할 필요는 없습니다.
- **기본 파라미터:** 현 단계에서는 충분한 출발점입니다. 개인화보다 일관된 기록이 먼저입니다.
- **목표 기억 유지율:** 우선 90%로 명시하고 실사용을 확인하겠습니다.
- **안정도 21일 = 정착:** 내부 지표로는 가능하지만 표현은 수정하는 편이 좋습니다.

FSRS의 안정도는 모델상 회상 확률이 90%까지 떨어지는 데 걸리는 시간입니다. 따라서 21일은 ‘완전히 암기했다’는 인증이 아닙니다. **‘복습 간격이 길어진 단어’ 정도로 설명**하고 계속 복습 대상에 두세요. (awesome-fsrs wiki)

문서의 §1-4는 ‘다시/어려움 모두 10분’, §2-3은 ‘어려움 15분’으로 다릅니다. 실제 스케줄러가 반환한 예정 시각을 출제와 화면 표시 모두에서 사용하도록 정리해야 합니다.

**7. 신규 출제 순서 — 파일 순서는 바꾸되, 처음부터 복잡한 추천 알고리즘은 필요 없습니다.**

우선은 다음 정도면 충분합니다.

1. 학습 우선순위를 `핵심 상·중·하` 정도로 나눕니다.
2. 같은 우선순위 안에서 분야와 품사를 섞습니다.
3. 명확한 혼동 묶음은 첫 학습에서 하루에 하나씩 배정하는 방식을 시험합니다.
4. 각각 익숙해진 뒤에는 비교 복습에 함께 등장시킵니다.

예를 들어 `以上·以下·以内·以外`를 첫날 한꺼번에 넣는 방식과, 이미 배운 뒤 비교하는 방식은 목적이 다릅니다. 처음부터 계속 붙여 내거나 영구적으로 떨어뜨려 놓을 필요는 없습니다.

또한 **출제 순서 변경과 단어 ID 변경은 분리**해야 합니다. 파일을 정렬했더니 기존 학습 기록의 연결이 바뀌는 문제는 반드시 막아야 합니다.

**8. 구조·유지보수 — 모듈 방향에는 동의, 테스트 46개만으로 충분하다고 판단할 수는 없습니다.**

현재 규모에서는 더 복잡하게 구조를 나누기보다, 학습 기록을 잃거나 잘못 갱신하는 상황을 확인하는 편이 중요합니다.

우선 확인할 시나리오는 다음과 같습니다.

| 상황 | 확인할 결과 |
|---|---|
| 평가 버튼 연속 클릭 | 리뷰가 한 번만 저장됨 |
| 저장 직후 앱 종료·새로고침 | 기록과 다음 복습 시각이 일치함 |
| 같은 날 여러 번 세션 시작 | 하루 신규 한도를 중복 지급하지 않음 |
| 백업 내보내기 → 새 환경에서 복원 | 카드·로그·설정·날짜가 동일하게 복원됨 |
| 단어의 급수·순서 변경 | 기존 학습 기록이 유지됨 |
| 업데이트 후 오프라인 실행 | 필요한 화면·단어 데이터가 함께 작동함 |

Capacitor 전환을 위한 `platform/` 분리는 좋은 선택입니다. 다만 실제 전환에서는 키보드가 버튼을 가리는 문제, 앱 복귀, 음성 재생, 파일 저장·공유 등도 확인해야 하므로 **‘모듈만 교체하면 끝’이라고 전제하지는 않는 편이 좋습니다.**

파이프라인에서는 **‘음성 파일이 있으면 건너뜀’**이 눈에 띕니다. 예문을 수정했는데 파일명이 그대로라면 이전 음성이 남을 수 있습니다. 생성 입력 문장·읽기·목소리 설정이 달라지면 다시 생성하고, 앱의 캐시도 새 파일을 받도록 버전을 바꾸세요.

Web Speech 폴백 역시 항상 기기 내 처리인 것은 아닙니다. 로컬·원격 음성이 구분되므로, 런타임 외부 호출 금지가 원칙이라면 로컬 음성만 허용하거나 폴백을 끄는 처리가 필요합니다. (MDN SpeechSynthesisVoice.localService)

**9. 빠진 것·미뤄도 되는 것 — 지금 가장 필요한 것은 짧은 세션을 실제로 끝낼 수 있게 하는 기능입니다.**

**‘매일 5~10분’과 ‘기한이 된 복습 전부 + 신규 + 10분 뒤 재출제까지 완료’는 충돌할 수 있습니다.**

저라면 다음을 먼저 넣겠습니다.

- **5분/10분 세션 종료:** 시간이 되면 현재 문제까지만 마치고 종료할 수 있게 합니다.
- **기다리지 않고 나가기:** 재출제 예정 카드는 저장하고 다음 접속에서 이어갑니다.
- **미처리 복습 수 표시:** 오늘의 짧은 세션을 끝낸 것과 복습을 전부 처리한 것을 구분합니다.
- **직전 평가 취소:** 오터치가 복습 일정을 바꾸지 않게 합니다.
- **문제 오류 표시·일시 제외:** 의심스러운 단어를 계속 외우게 하지 않습니다.
- **마지막 백업 시점 표시:** 백업 기능이 실제 복구 수단으로 쓰이게 합니다.

통계의 A/B/C 등급도 재검토를 권합니다. 자기평가·객관식·입력형·같은 날 재시도까지 섞은 정답률은 해석하기 어렵습니다. 우선 **유형별 정답률, 힌트 없이 맞힌 비율, 다음 날 이후 첫 시도의 정답률**을 분리해 보여주세요. 시험 성적표를 연상시키는 등급보다 사용자가 무엇을 더 공부해야 하는지 잘 알려줍니다.

반대로 **N1 대량 제작, 정교한 적응형 테스트, 추가 목소리, 이미지 카드, 다른 언어 범용화, 스토어 포장**은 뒤로 미뤄도 됩니다. 이후 시험 대응 기능을 하나 확장한다면 문맥 속 의미·용법 확인을 우선 검토하겠습니다.

제가 다음 개발 순서를 정한다면 다음과 같습니다.

1. **단어 검증 정책 수정:** 무관한 단어로 교체한 목록부터 재검토합니다.
2. **판정 규칙 수정:** 힌트, C의 답 모호성, A/B/C와 FSRS의 관계를 정리합니다.
3. **짧은 세션 완성:** 대기 없이 종료·재개하고 신규 0개인 날을 지원합니다.
4. **현재 수준에 맞는 단어로 2주간 직접 사용:** 소요 시간, 다음 날 회상, 부당한 오답, 중단 이유를 기록합니다.
5. **그 결과로 N3·N2 핵심 단어장과 간단한 완주 계획을 확장합니다.**

지금 가장 먼저 확인할 질문은 **“단어 700개를 더 만들 수 있는가?”보다 “이 앱으로 일주일 전에 공부한 단어가 실제로 떠오르고, 내일도 부담 없이 켤 수 있는가?”**입니다.
